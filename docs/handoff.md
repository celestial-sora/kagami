# Stable release v2.0.0 · 2026-10-10

The maintainer authorizes a stable release. The release/** workflow accepts only release/v<VERSION> pointing at the current main commit with successful Checks CI. It packages committed source, generates a tag-pinned Ubuntu installer and SHA256SUMS, uploads a draft, downloads/verifies all asset bytes, then publishes as latest stable. The public README/install guide use the latest stable installer; explicit KAGAMI_REF and the development source installer remain available. This is a source/build installer release, with Smart View experimental and remaining physical-device acceptance recorded in docs/releases/v2.0.0.md. Contributor: celestail-sora.

# Current handoff · 2026-10-10

Ubuntu native GTK4 receiver in `apps/receiver/kagami_receiver`: Samsung Smart View, AirPlay, USB and authorized ADB Wi-Fi feed a shared crop/rotation/mirror/fit/FPS pipeline and persistent real V4L2 camera output. The maintainer requests direct main integration after feature CI, no PR, contributor celestail-sora, and one-command curl installation.

The latest request adds AirPlay and removes the URL/QR connection system. Browser client, HTTPS/WebRTC host, QR-generating Rust shell, V1 installer, TLS/config helpers and obsolete tests/dependencies were removed. Reusable V4L2 identity guard moved into the current receiver; no V1 runtime imports remain. Existing user settings/previous installed app versions are preserved by updates, not used as new connection flows.

AirPlay uses separate UxPlay 1.73.2 at 4764e4619e8924f43601d778277fc9f0bf280597, Avahi, loopback-only H264/RTP and an unprivileged decoder normalized to a fixed letterboxed 1280×720 source canvas. It requires a same-LAN AirPlay sender, not Wi-Fi Direct. Native Galaxy Smart View remains Miracast. AirPlay audio now plays through the desktop PulseAudio/PipeWire output for speakers and OBS Desktop Audio, as requested by the maintainer; recording remains disabled and personal UxPlay config is ignored. Stop reaps the owned process group. Phone identity/orientation preset tracking and Apple interoperability remain unverified.

Smart View uses the fixed polkit broker with explicit selected-adapter disconnection consent and EOF restoration. RTL8821CE/rtw88_8821ce currently lacks advertised P2P client/GO despite Windows Miracast history. Diagnose Linux driver options before concluding new hardware is necessary; no driver/network settings were changed here.

Default nodes: Screen Input video11, Virtual Camera video10; installer skips occupied physical slots and reuses identified nodes. The source/camera writer and device guards remain mandatory. Source entry: `bash tools/run-receiver.sh`; see [installation](installation.md), [AirPlay](airplay-ubuntu.md), [Smart View](smartview-ubuntu.md), [ADB](receiver-setup.md), [tests](testing.md), [validation](validation.md).

The maintainer now confirms real iPad discovery and mirrored video in both Kagami and OBS on Ubuntu 26.04. Other Apple devices, Galaxy/P2P, Discord, network restoration and long-session latency/FPS remain open. Archived V1 handoff/plan and supplied architecture are historical context; current instructions supersede conflicting workflows.

Idle-screen correction: the maintainer reports gaming for over ten minutes, but static screens going black. Both the shared controller's three-second slate and AirPlay's four-second media timeout treated missing changed frames as a lost session. AirPlay now holds its latest frame at the camera FPS and relies on fixed, flushed protocol events from the patched owned backend. Video teardown/TCP EOF, final control EOF, reset and missing client feedback still clear the output. The backend capability marker is required, so updating rebuilds UxPlay once; unchanged later installs reuse it. All 59 contracts/media tests pass locally, plus native callback/real loopback EOF regressions, timestamps, discovery and GTK. The ten-minute protocol test advances 600 logical timer ticks; actual long static-screen acceptance on the iPad remains open.

Camera size correction: OBS held the output at 1280×720, preventing a switch to 1920×1080. The maintainer confirms 1080p now works after releasing the consumer. The writer checks supported dimensions before buffers or the AirPlay listener start and provides release/retry guidance; the desktop explains the Stop → deactivate consumer → select size → Start → reactivate sequence. All 62 contracts/media tests and GTK/Xvfb pass locally. A real named video10 consumer reads complete 1920×1080 YUY2 frames, rejects a change to 720p while that consumer holds 1080p, and permits restarting at the held size. AirPlay input remains the fixed 1280×720 canvas. Backend recipes are unchanged.

Desktop audio correction: the previous `-as 0` explicitly muted AirPlay. UxPlay now uses `pulsesink client-name=Kagami`; the desktop explains matching OBS Desktop Audio to the selected Ubuntu output. Compressed audio appsrc queues are bounded to 64 buffers/two seconds, with a required `KAGAMI_AIRPLAY_AUDIO_V1` marker. Updating rebuilds the backend once. Missing audio plugins and runtime output failures are reported. Synthetic ALAC decoding, stalled-queue limits, Stop, desktop audio connection, all 64 contracts/media checks and GTK pass locally; actual iPad speakers/OBS capture and audio/video sync remain open.

Desktop settings persistence: installer settings previously existed but GUI edits were never written back, the launcher froze install-time defaults, and Start reset crop. The desktop now saves validated explicit choices after a short pause and on Start/close, restoring global framing/output controls on reopen and preserving crop across Stop/Start. The launcher reads settings on each invocation using old supported CLI flags so payload rollback remains usable. Settings use atomic owner-only files and preserve installer metadata and device presets; bad existing files are retained with a visible warning. Pairing codes, device identity, consent and running state are not saved. All 68 contracts/media tests and actual GTK/Xvfb autosave/reopen tests pass locally; backend recipes are unchanged.

Installer update controls: commit comparison before downloads, recipe/platform/backend reuse, numbered progress, preserved `previous` app pointer, `kagami versions`/`rollback`, and explicit `--repair`. Release tags work today; release artifacts/default stable channel are future work. Rollback switches app payload only, not shared system packages/backends.

Latest installer correction: absence of P2P is now an optional Smart View warning with exit 0 when AirPlay/common prerequisites pass. New installs default to AirPlay without P2P. UxPlay v1.73.2 gets its missing stdio.h include, fixing the reproduced GCC 15 implicit-printf-declaration build error on Ubuntu 26.04. Live authorized Ubuntu 26.04 installation now exits 0 without P2P. AirPlay doctor and owned-process start/stop pass; a real video10 consumer reads black waiting frames. Actual Apple media/OBS remains pending. See the current validation entry and successful feature CI.
