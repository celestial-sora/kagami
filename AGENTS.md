# Kagami maintainer direction

- Primary desktop is Ubuntu 24.04/26.04. Samsung Smart View remains the main target; AirPlay is an additional iPhone/iPad/Mac receiver. USB and authorized ADB Wi-Fi are fallback transports.
- The maintainer explicitly removed the browser URL/QR pairing system. Do not restore HTTPS/WebRTC/browser pairing, QR generators, the V1 Rust shell or install-v1.sh. Historical documents and the supplied architecture-v2.md are archival context only.
- Read docs/handoff.md, docs/receiver-audit.md and docs/validation.md before changes. docs/architecture-v2.md preserves the supplied document verbatim; later maintainer instructions override rollout/toolkit choices.
- apps/receiver/kagami_receiver is the Python/GTK4 reference desktop. All transports feed the shared crop/rotate/mirror/fit/FPS pipeline and persistent V4L2 writer. No required Android Kagami app or cloud/account.
- The maintainer-approved app artwork is apps/receiver/kagami_receiver/assets/kagami-icon.png. Preserve this RGBA source; hicolor PNGs pad it to a square and resize with alpha intact. The GTK application, window icon and desktop launcher use io.kagami.Host; the installer copies icons into the user's XDG data directory.
- Never run the desktop/media as root or write into physical cameras. Reuse the driver/label guard in kagami_receiver.v4l2 and two distinct named loopbacks. Never unload another camera to free a slot.
- Smart View is experimental MiracleCast control + RTP/MPEG-TS/H264. Only P2P-client/P2P-GO under supported interface modes count; TX/RX mentions do not. The authoring RTL8821CE/rtw88_8821ce does not advertise these modes; Windows Miracast history means this is a current Linux-driver limitation, not proof that the hardware is incapable.
- Smart View's fixed root-owned polkit broker hands only the explicitly selected adapter to MiracleCast. Require explicit consent for selected-adapter disconnection. EOF restores management. Never silently stop global networking or add passwordless sudoers.
- AirPlay uses an owned UxPlay 1.73+ child and a loopback-only H264/RTP bridge. Use -rc /dev/null to ignore recording/pipeline overrides in personal config. The maintainer now requests audio through Ubuntu's desktop output for speakers and OBS Desktop Audio; use the user-session PulseAudio/PipeWire sink. Do not record frames or audio. It needs same-LAN Avahi discovery, not P2P. Native Samsung Smart View is not an AirPlay sender.
- AirPlay normalizes input into a fixed letterboxed 1280x720 canvas before the shared crop. Do not promise phone identity, saved wireless-device presets, orientation tracking, automatic reconnect or glass-to-glass latency until verified.
- Keep bounded queues/logs, black slate on disconnect, process-group reaping and reliable Stop/close. The maintainer now requests remembering explicit desktop choices: transport, loopback paths, dimensions/FPS, selected adapter and framing/crop controls/preset label. Save these locally; never persist pairing secrets, adapter-disconnection consent, wireless phone identity or an automatic Start. No screen files by default.
- install.sh is the one-command curl Ubuntu installer: dependencies, pinned MiracleCast/UxPlay builds as the caller, fixed root-owned helpers, DKMS camera service and user launcher. Preserve settings/presets and previous app versions. Report MOK/reboot camera requirements as pending; missing P2P only disables Smart View and must not block successful AirPlay installation; never claim phone compatibility from installation alone.
- The installer must resolve/check the active commit before downloading, skip identical updates, reuse verified unchanged backend builds, show stage progress and preserve V2 app rollback. Support release tags; a stable Release channel remains future work until releases/artifacts exist.
- Run headless contracts, ShellCheck and relevant opt-in KAGAMI_TEST_GST=1 synthetic media checks with fatal-criticals; GTK uses Xvfb. Actual Apple/Galaxy/P2P/V4L2/OBS and Secure Boot acceptance remain open. Do not run host privileged/network-changing acceptance implicitly.
- No PR. Publish through the GitHub connector/Codex agent, validate in a feature branch, then integrate main once after CI. Credit contributor celestail-sora (or celestail-duck); linked account/repo owner is celestial-sora.
